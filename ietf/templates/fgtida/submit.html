Submit a contribution

Submit to an existing working group, or choose No working group yet when no working group covers your proposal. All routes require your DataTracker account. The selected group's recipients (or FG management for No working group yet) receive the contribution through the existing notification service.

Submissions are public. Use the FG-TIDA specification template and include your title, authors, scope, technical content and references.

1. GitHub repository

  1. You need your own GitHub account. Create one if needed, then sign in.
  2. Open the specification template, choose Use this template → Create a new repository, select your own username as Owner and make the repository public.
  3. Replace the example RST chapters with your contribution. Keep every referenced image, diagram and bibliography in the documentation folder, normally src/doc.
  4. Follow the template README to check the build. Save your completed changes as a commit and copy its full 40-character SHA from GitHub.
  5. Below, choose GitHub and enter your repository URL, commit SHA, source folder and entry document. Do not upload a file.

The DataTracker archives the selected source and assets at that exact commit. Later repository changes do not replace this submission. WG editors establish the official repository in the adopting WG's organisation after adoption.

2. RST source ZIP

  1. No GitHub account is needed. Open the same template and choose Code → Download ZIP.
  2. Extract it on your computer. Edit the .rst text files and include every referenced image, diagram and reference file under the documentation folder.
  3. Keep the folder structure and use relative paths, such as figures/architecture.svg. Check the build using the README instructions if possible.
  4. Compress your completed source folder into one ZIP, at most 10 MB (500 entries / 30 MB expanded). Exclude installed environments, generated output and secrets.
  5. Choose RST source ZIP below, upload it and enter the full path to its main RST file inside the ZIP, such as my-contribution/src/doc/index.rst. Leave GitHub fields empty.

The original ZIP is retained. The maintained source package contains the entry document's folder and its subfolders. Include all supporting files there.

3. Word (.docx) — exceptional fallback, discouraged

Use this route if you cannot prepare RST, even with the ZIP method. No GitHub account or RST knowledge is required.

  1. Write your contribution using Word heading styles. Include title, authors, scope, references, captions and embedded figures.
  2. Resolve all tracked changes. Embed images instead of linking to files on your computer or the web. Save as .docx, at most 10 MB.
  3. Choose Word below and upload that file. Leave the repository, commit, source folder and entry document fields empty.
  4. The DataTracker automatically converts it to RST and extracts supported images. After submission, check the preview, assets and downloadable RST package against your Word original.
  5. Confirm the conversion on your contribution page. Editors cannot adopt it until you confirm. If tables, equations, drawings or references are missing or incorrect, contact the secretariat; do not confirm an inaccurate conversion.

The Word original remains archived. Verified RST is used for subsequent standards work. Conversion is not technical approval.

For assistance, contact the secretariat. Receipt and WG notifications use the same mail workflow for all three routes.
